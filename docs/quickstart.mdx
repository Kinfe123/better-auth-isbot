# Quickstart

`better-auth-is-bot` blocks bot traffic from your better-auth routes by inspecting the `User-Agent` header on every incoming `POST` and `GET` request. When the [`isbot`](https://www.npmjs.com/package/isbot) library recognises the user agent as a bot, the plugin returns a `400 Bad Request` before the request reaches any of your auth handlers. No other HTTP methods are evaluated — they pass through untouched.

## Add the package

Install `better-auth-is-bot` alongside your existing `better-auth` setup:

```bash
npm install better-auth-is-bot
# or
pnpm add better-auth-is-bot
# or
yarn add better-auth-is-bot
```

`better-auth ^1.2.10` must already be installed. No other prerequisites are required.

## Protect all routes with zero configuration

Import `IsBot` and pass it into the `plugins` array of your `betterAuth` configuration. Called with no arguments, it protects every `POST` and `GET` route automatically:

```typescript
import { betterAuth } from "better-auth";
import { IsBot } from "better-auth-is-bot";

const auth = betterAuth({
  baseURL: "http://localhost:3000",
  database: /* your database config */,
  plugins: [
    IsBot() // All POST and GET routes are protected
  ],
});
```

That is the complete setup. No environment variables or additional configuration files are needed.

## Protect specific routes only

Pass a `protectedEndpoints` array to limit bot-blocking to particular paths. Wildcard segments cover entire route groups:

```typescript
const auth = betterAuth({
  baseURL: "http://localhost:3000",
  database: /* your database config */,
  plugins: [
    IsBot({
      protectedEndpoints: ["/login", "/register", "/api/auth/*"]
    })
  ],
});
```

When `protectedEndpoints` is set, only paths that match one of the listed patterns are checked. Every other route passes through unchanged.

## Customize the blocked-bot response

Supply an `errorMessage` string to replace the default message bots receive:

```typescript
const auth = betterAuth({
  plugins: [
    IsBot({
      errorMessage: "Access denied for automated requests."
    })
  ],
});
```

When a bot is blocked, the plugin always returns HTTP `400` with this JSON body shape — using your custom string in place of the default:

```json
{
  "message": "BOT_DETECTED",
  "error": "BAD_REQUEST"
}
```

## What gets detected

The `isbot` library recognises search engine crawlers (Googlebot, Bingbot), social media bots (Facebook, Twitter), monitoring and testing tools, and many other automated user agents. Requests that arrive without a bot user agent on a protected route are passed through normally.
