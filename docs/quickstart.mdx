# Quickstart

`better-auth-is-bot` is a plugin for [better-auth](https://better-auth.com) that blocks bot traffic from your authentication routes. It inspects the `User-Agent` header on every incoming `POST` and `GET` request using the [`isbot`](https://www.npmjs.com/package/isbot) library. When a bot is detected, the plugin returns a `400 Bad Request` before the request reaches your auth handlers.

## Install the package

Add `better-auth-is-bot` to your project alongside `better-auth`:

```bash
npm install better-auth-is-bot
# or
pnpm add better-auth-is-bot
# or
yarn add better-auth-is-bot
```

## Protect all routes with zero configuration

Pass `IsBot()` into your `better-auth` plugins array. With no arguments, every `POST` and `GET` route handled by better-auth is protected automatically:

```typescript
import { betterAuth } from "better-auth";
import { IsBot } from "better-auth-is-bot";

const auth = betterAuth({
  baseURL: "http://localhost:3000",
  database: /* your database config */,
  plugins: [
    IsBot() // All POST and GET routes are protected
  ],
});
```

That is the entire setup. No additional environment variables or configuration files are required.

## Protect specific routes only

Pass a `protectedEndpoints` array to restrict bot-blocking to particular paths. Wildcard segments are supported:

```typescript
const auth = betterAuth({
  baseURL: "http://localhost:3000",
  database: /* your database config */,
  plugins: [
    IsBot({
      protectedEndpoints: [
        "/auth/*",
        "/admin/*",
        "/api/protected/*"
      ],
      errorMessage: "This endpoint does not allow automated requests. Please use a regular browser."
    })
  ],
});
```

When `protectedEndpoints` is set, only paths that match one of the listed patterns are checked. All other routes pass through unchanged.

## What happens when a bot is blocked

Any request whose `User-Agent` matches a known bot pattern on a protected route receives this response:

```json
{
  "message": "BOT_DETECTED",
  "error": "BAD_REQUEST"
}
```

The `message` field uses `"BOT_DETECTED"` by default, or the string you supply as `errorMessage`. The HTTP status is always `400`. Requests that use methods other than `POST` and `GET` are never blocked regardless of route configuration.

## What `isbot` detects

The underlying `isbot` library covers search engine crawlers (Googlebot, Bingbot), social media bots (Facebook, Twitter), monitoring and testing tools, and many other automated user agents.
