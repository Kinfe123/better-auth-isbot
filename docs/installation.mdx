# Installation

`better-auth-is-bot` is a plugin for `better-auth` that blocks bot traffic by inspecting the `User-Agent` header on incoming POST and GET requests. It has no required configuration — dropping it into the `plugins` array is enough to start protecting every route.

## Prerequisites

Your project must already have `better-auth` installed and configured. `better-auth-is-bot` declares `better-auth ^1.2.10` as a dependency, so any compatible version in that range works.

## Add the package

Choose the package manager your project uses:

```bash
npm install better-auth-is-bot
# or
pnpm add better-auth-is-bot
# or
yarn add better-auth-is-bot
```

## Register the plugin

Import `IsBot` from `better-auth-is-bot` and add it to the `plugins` array in your `betterAuth` configuration. No additional options are needed to get started:

```typescript
import { betterAuth } from "better-auth";
import { IsBot } from "better-auth-is-bot";

const auth = betterAuth({
  // ... your other better-auth configuration
  plugins: [
    IsBot() // Protects all POST and GET routes by default
  ],
});
```

When a request arrives with a bot `User-Agent`, the plugin immediately returns a `400 Bad Request` response and the request never reaches your handler:

```json
{
  "message": "BOT_DETECTED",
  "error": "BAD_REQUEST"
}
```

## Configure protected routes and error messages

`IsBot` accepts an optional `IsBotOptions` object with two fields:

```typescript
export interface IsBotOptions {
  protectedEndpoints?: string[];
  errorMessage?: string;
}
```

`protectedEndpoints` limits bot-checking to a specific list of paths. Wildcard segments are supported — for example, `/auth/*` matches any sub-path under `/auth/`. When this field is omitted, every POST and GET route is checked.

`errorMessage` replaces the default `"BOT_DETECTED"` string in the response body. Use it to return a human-readable explanation to any client inspecting the response.

A complete example combining both options:

```typescript
const auth = betterAuth({
  baseURL: "http://localhost:3000",
  database: /* your database config */,
  plugins: [
    IsBot({
      protectedEndpoints: [
        "/auth/*",
        "/admin/*",
        "/api/protected/*"
      ],
      errorMessage: "This endpoint does not allow automated requests. Please use a regular browser."
    })
  ],
});
```

## Verify the setup

With your auth server running, send a request that carries a known bot `User-Agent` — for example, `Googlebot/2.1` — to any protected route. The plugin should respond with `400` and the `BOT_DETECTED` message. A request from a normal browser `User-Agent` passes through unchanged.

Only POST and GET requests are evaluated. Requests using any other HTTP method pass through without any bot check, regardless of the `User-Agent`.
